3) Conclusion on TuCop's integration shape:
   The TuCopWallet does NOT call Squid's HTTP API directly.
   It calls Valora's getSwapQuote cloud function:

   src/web3/networkConfig.ts:263:
     const GET_SWAP_QUOTE_URL = `${CLOUD_FUNCTIONS_MAINNET}/getSwapQuote`

   Used by:
     - src/swap/useSwapQuote.ts        (in-app swap)
     - src/gold/useGoldQuote.ts        (gold buy / sell)
     - src/dollarsSpend/useMultiSwapQuote.ts  (dollars-spend feature)

   Valora's getSwapQuote is the actual Squid integrator. Valora attaches
   ITS OWN x-integrator-id when proxying to Squid. The wallet only sees
   `quote.details.swapProvider === 'squid'` in the response and forwards
   `unvalidatedSwapTransaction` as a TransactionRequest.

4) Implication for attribution under EIP-7702:
   Since integratorId attribution is established at the API-call layer
   (Valora -> Squid HTTP request), it is NOT a function of on-chain
   `tx.origin` or `msg.sender`. The 7702 BatchExecutor wrapping changes
   only the on-chain shape of the call to SquidRouter
   (`0x4c363649D45d93A39Aa2E72cB1bEae5e25C63E88`) and does not affect
   the off-chain attribution path.

   The actual TuCop "IntegratorId" to fill in for any outreach is held
   on Valora's side, NOT in this repo. There is no .env entry to expose.
